ProblemBackgroundMethodNext

The agent writes what it sees as one long vector H

H = Σk s(k) ⊙ p(k)

s(k): the vector of the object at position k  ·  p(k): the vector of position k

Every object and every position has its own random vector of +1s and −1s.

Bind (⊙): multiply two vectors entry by entry. “key ⊙ ahead” means “the key is ahead”.

Bundle (Σ): add the bound pairs. H holds the whole view in one vector.

Unbind: a ±1 vector bound with itself gives all ones, so binding again with the same vector undoes a binding.

Background · encoding a state

Source. Draft slide 3: H = Σk s(k) ⊙ p(k), where s(k) is the object encoding and p(k) its positional encoding (the speaker note reads s(object at k)).

The vectors here are schematic: 8 entries, chosen at random. Real hypervectors have thousands of entries; there, two random vectors are nearly orthogonal, so the bound pairs in H barely interfere.

The view (left) uses the three positions of draft slide 5: ahead, left and right of the agent.

Step 4 is the fact the method relies on: for entries of ±1, x · x = 1, therefore s(key) ⊙ s(key) ⊙ p = p.

ProblemBackgroundMethodNext

The agent takes the action whose weights best match H

𝒜 = {A1, A2, …, An}

one learned weight vector for each of the n actions

sim(Ai, H) = Ai · H / √D

dot product: multiply entry by entry, then add up; D is the vector length

a* = argmaxi sim(Ai, H)

the best action is the one with the largest similarity

The example has D = 5. The weights are the draft's Wpickup; H is a view with only the key, straight ahead.

ProblemBackgroundMethodNext

Step 1, unbind: cancel the key out of Wpickup

U = Wpickup ⊙ key

Wpickup learned to answer “key at some position”. Binding it with the key cancels the key (key ⊙ key = 1) and leaves the positions.

Compare U with each known position vector. Dividing by D gives how much of each position U contains.

Read: pickup fires mostly when the key is ahead (+0.06), a little when it is left, and is pushed down when it is right.

Method · step 1, unbind

Source. Draft slide 5: U = Wpickup ⊙ key and the table p1 (ahead) +0.06, p2 (left) +0.02, p3 (right) −0.06.

The toy vectors (5 entries, chosen so that every number of draft slides 5 and 6 comes out exactly): key = [+1, −1, +1, −1, +1]; p1 = [+1, +1, −1, −1, +1]; p2 = [−1, +1, +1, −1, −1]; p3 = [−1, −1, +1, +1, −1]. Then U = [+0.10, +0.10, +0.10, −0.10, +0.10], and U · pj / 5 gives +0.06, +0.02, −0.06.

Which similarity? The draft's table matches U · p / D, not the U · p / √D of slide 3 (that would give 0.13, 0.04, −0.13). Dividing by D = p · p makes each number the coefficient of pj in U, which is what step 2 needs.

ProblemBackgroundMethodNext

Step 2, clean up: rebuild U from the known positions

M = 0.06 p1 + 0.02 p2 − 0.06 p3

Each position vector is weighted by its similarity from step 1, and the weighted vectors are added.

Why not keep U? U also carries everything else pickup learned, now scrambled by the unbinding, which is noise. M keeps only the part that lies along known positions.

Intuition from the draft: we reconstruct the key's positional information from the known position vectors, rather than keeping the noisy unbound vector directly.

Method · step 2, clean up

Source. Draft slide 5, M = 0.06 p1 + 0.02 p2 − 0.06 p3, and its speaker note (the intuition, quoted on the slide).

The numbers use the toy vectors of slide 6's notes: M = [+0.10, +0.14, −0.10, −0.14, +0.10].

A caveat of the toy. With only 5 entries the toy's p3 is exactly −p1, so the positions are far from orthogonal. With thousands of entries random position vectors are nearly orthogonal, and M is close to the true projection of U onto the positions.

ProblemBackgroundMethodNext

Step 3, rebind and subtract the key's part

key ⊙ M

Binding M with the key again puts “key at those positions” back: this is the key's contribution to Wpickup.

W′pickup = Wpickup − key ⊙ M

Subtract it, entry by entry.

W′pickup keeps what pickup learned about everything else. Only the part that answered “key at a position” is gone.

Method · step 3, rebind and subtract

Source. Draft slide 6: Original Wpickup = [+0.10, −0.10, +0.10, +0.10, +0.10]; key contribution key ⊙ M = [+0.10, −0.14, −0.10, +0.14, +0.10]; after subtraction W′pickup = [0.00, +0.04, +0.20, −0.04, 0.00]. Each entry checks: for example 0.10 − (−0.10) = 0.20.

The rebinding uses the toy key of slide 6's notes: key ⊙ M = [+1, −1, +1, −1, +1] ⊙ [+0.10, +0.14, −0.10, −0.14, +0.10].

After the edit, the key ahead no longer pulls toward pickup

Pickup's similarity with H = key ahead (slide 5), before and after the edit

Ideal: about 0, no pull either way, as in an agent that never learned the key. The 5-entry toy overshoots below 0 because its position vectors are not orthogonal (p3 = −p1).

The draft's edited weights for two actions, on one observation

Method · the result in the toy

Left, computed from the draft's vectors and the toy H of slide 5: before, Wpickup · H = 0.30, so 0.30 / √5 = +0.13; after, W′pickup · H = −0.28, so −0.28 / √5 = −0.13.

Why the toy overshoots. Because p3 = −p1 in the toy, M counts the "ahead" part twice (0.06 p1 − 0.06 p3 = 0.12 p1). With nearly orthogonal positions, W′ · (key ⊙ p) would be close to 0 for every position.

Right, from draft slide 7: W′pickup = [0.00, 0.04, 0.20, −0.04, 0.00], W′turn = [0.00, −0.04, −0.20, 0.04, 0.00], pickup logit +0.05, and a second logit −0.05. To check: the draft does not say which observation gives these logits. H = [+1, −1, +1, +1, −1] reproduces them (0.12 / √5 = 0.054), so it is used here; any H with entries 2 to 4 equal to −1, +1, +1 gives the same. The draft labels the second logit "Forward" but its weights W′turn; the slide says "turn".

ProblemBackgroundMethodNext

The edit is three vector operations on the trained weights

No retraining. The edit needs no environment steps and no gradient updates, only products and sums of vectors of length D.

It uses the structure. It works because the policy's weights are built from bound object–position pairs: the skill can be found by its object, here the key.
